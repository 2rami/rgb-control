# rgb-control

NZXT CAM 없이 조명·수랭·LCD 를 한 프로그램으로 다루는 웹 대시보드.

CAM, L-Connect, Razer Synapse, G.SKILL 유틸리티를 전부 끄고 그 자리를 대신한다.
브라우저에서 `http://127.0.0.1:5000` 하나만 열면 된다.

> 개인 컴퓨터 한 대를 상대로 만들었고, 지금도 그 한 대에서만 검증돼 있다.
> 부품 구성이 다르면 손봐야 할 곳이 있다. 아래 **내 구성**을 먼저 읽어 달라.

---

## 무엇을 대신하나

| 원래 쓰던 것 | 이걸로 |
|---|---|
| NZXT CAM | 수온 읽기, 펌프 곡선, 크라켄 LCD |
| L-Connect | 리안리 유니팬 조명 |
| Razer Synapse | Razer ARGB 컨트롤러 (여기선 그래픽카드 LED) |
| G.SKILL Trident Z | 램 조명 |

**CAM 에 있는데 여기 없는 것**: 게임 오버레이, 클라우드/계정 기능.

## 되는 것

**조명**
- 팬 768 LED, 램, 그래픽카드, 스피커를 한 색으로 묶거나 따로 지정
- 효과: 물결 · 순환 · 숨쉬기 · 고정 · 은은 · 아이스 · 깊이 · 화면 동기화
- **소리 반응 3종** — 스피커로 나가는 소리를 루프백으로 따서 반응한다.
  마이크가 아니라 실제 재생 중인 소리라 방 안 소음에 안 흔들린다.
- 케이스 그림을 눌러 부품 하나만 다른 색으로. 유니팬은 안쪽 링과 바깥
  테두리가 서로 다른 채널이라 따로 누른다.

**수랭 (NZXT Kraken Elite)**
- 수온·펌프 rpm 읽기
- 펌프: 수온 곡선 자동 / 손으로 고정 (안전 하한 60%)

**LCD (640×640 원형)**
- 조명과 같은 색 / CPU·GPU 상태판 / 모니터 실시간 비추기 / 영상·GIF / 끄기
- 유튜브 **재생목록**을 이어서 재생, 소리는 스피커로
- Giphy GIF 무한 반복
- 초당 30장, 256색 이상

**모니터를 끄면 조명도 끈다**
- 모니터 전원 버튼으로 꺼도 알아챈다. 조명·램·글카·LCD 가 같이 꺼지고
  화면을 켜면 원래 설정으로 돌아온다. LCD 는 따로 뺄 수 있다
- 켜고 끄는 것이 아니라 색만 검게 덮는 방식이라, 켜질 때 저절로 복구된다

**트레이 아이콘**
- 트레이가 주인이다. 아이콘이 있으면 켜져 있는 것이고, 끝내면 다 꺼진다
- 더블클릭하면 대시보드가 열린다. 우클릭 메뉴에서 수온·펌프·모니터 상태를
  보고 조명 켜기/끄기, 효과, LCD 화면을 바꾼다
- 아이콘 색이 지금 조명색이다. 조명이 꺼져 있으면 테두리만 남는다

**자동 시작**
- 로그인 30초 뒤 UAC 없이 트레이가 뜬다 (작업 스케줄러 + 최고 권한)
- CAM·Razer 자동 시작을 꺼 두고, 지운 값은 백업해서 되돌릴 수 있다
- 마지막에 고른 설정(효과·색·펌프·LCD)을 기억했다가 그대로 되돌린다

## 설치

**필요한 것**

- Python 3.11 이상
- [OpenRGB](https://openrgb.org/) — 서버 모드로 쓴다
- [ffmpeg](https://ffmpeg.org/) — LCD 영상용 (`ffmpeg`, `ffplay` 둘 다 PATH 에)
- Rust (선택) — LCD 를 빠르게 쓰려면 아래 Q565 참고

```bash
pip install -r requirements.txt
```

**Q565 압축기 (LCD 를 쓸 거면 사실상 필수)**

크라켄 Elite 는 Q565 로 보내야 빠르다. 순수 파이썬 구현은 한 장에 500ms 라
못 쓴다. Rust 판을 만들어 넣는다.

```bash
git clone https://github.com/brokenmass/AIOLCDUnchained
cd AIOLCDUnchained
pip install maturin
python -m maturin build --release
pip install target/wheels/q565_rust-*.whl
```

없어도 그림은 나온다. 다만 느린 옛 경로로 물러나고, 오래 쓰면 장치가 굳는다.

**실행**

```
start.bat          # 관리자 권한으로 뜬다 (램 제어에 필요)
stop.bat           # 내리기
install_autostart.ps1   # 부팅 자동 시작 등록 (-Remove 로 해제)
```

브라우저에서 `http://127.0.0.1:5000`.

## 처음 한 번 해야 하는 것

**팬 자리 맞추기.** 허브는 "채널 3에 팬이 있다"까지만 안다. 그게 케이스의
위인지 옆인지는 전기적으로 알 방법이 없다. 그래서 한 번은 사람이 맞춰야 한다.

케이스 그림에서 팬을 누르고 **「어디야?」** 를 누르면 그 팬이 하얗게 켜진다.
엉뚱한 게 켜지면 **▸** 로 채널을 넘기면서 맞으면 멈춘다. `layout.json` 에
저장되므로 한 번만 하면 된다.

**모니터 전원 버튼 가르치기.**

```
python display.py --learn
```

껐다 켜라고 하면 전원 버튼으로 끄면 된다. 그때 빠지는 USB 장치를 기억해서
`monitor_usb.json` 에 적어 둔다. 왜 이런 게 필요한지는 아래 "모니터 전원
버튼은 윈도우에 아무 흔적도 안 남긴다" 를 보라. 안 해도 절전으로 화면이
꺼지는 것은 잡는다.

## 삽질해서 알아낸 것들

같은 하드웨어를 만지는 사람이 시간을 아끼길 바라며 적어 둔다.

### 리안리 유니팬 (Uni Hub SL Infinity)

- **채널 하나가 팬 하나가 아니다.** 포트 하나에 팬이 3개까지 줄줄이 물린다.
  채널 96 LED = 팬 3개 × 32. 채널을 통째로 끄면 멀쩡한 팬까지 꺼진다.
- 짝수 채널 = 안쪽 링, 홀수 채널 = 바깥 테두리.
- 채널당 상한이 96 이다. 144 를 요청하면 **오류 없이** 96 에서 잘린다.
- Direct 모드가 없다. Custom 모드로 써야 LED 를 하나씩 지정할 수 있다.
- 색과 별개로 장치 밝기 값이 있다. 기본 37/50 이라 255 를 줘도 74% 로 깎인다.

### 벤더 프로그램이 살아 있으면 아무것도 안 된다

세 번 당했다. 공통 증상이 고약하다 — **쓰기는 성공으로 돌아오는데 장치는
저쪽 색 그대로다.** 그래서 "이 장치는 제어가 안 되는구나" 하고 엉뚱한 결론에
이르기 쉽다.

| 프로그램 | 뭘 쥐고 있나 |
|---|---|
| G.SKILL `hid.exe` | 램 (SMBus) |
| Razer Synapse `RazerAppEngine` | Razer ARGB 컨트롤러 = 그래픽카드 LED |
| NZXT CAM | 크라켄 (USB 독점) |

`start_all.ps1` 이 시작할 때 앞의 둘을 죽인다. 그것만으로는 부족해서
자동 시작 자체도 꺼야 했다 — 로그인 때 저쪽이 먼저 뜨기 때문이다.

### 색 찾기 시험에 장치의 현재색을 쓰지 마라

"어느 채널이 그래픽카드인가"를 빨강으로 시험했다. 그런데 그래픽카드는 원래
빨간 상태였다. **안 바뀐 것과 맞은 것을 구분할 수 없어** 엉뚱한 채널을 두 번
정답으로 읽었다. 팔레트에서 현재색을 빼고 다시 하니 바로 나왔다.

### 크라켄 Elite LCD

- **전송 방식이 장치를 죽인다.** 버킷 경로는 한 장마다 HID 왕복을 7번쯤 한다
  (조회·지우기·만들기·열기·닫기·전환). 그러면 HID 통로가 망가져서 수온조차
  못 읽고, **USB 를 껐다 켜도 안 풀린다. 전원을 완전히 끊어야 산다.**
  빠른 경로는 왕복이 2번이다.

  ```
  버킷 (GIF)   초당 47장 -> 보낸 뒤 수온 읽기 실패
  빠른 (Q565)  초당 56장 -> 수온 읽기 정상
  ```

- 빠른 경로 (Elite = PID `300C`, 자료 종류 `0x08` = Q565):

  ```
  write([0x36, 0x01, 0x00, 0x01, 0x08])   # 네 번째 1 이 "빠른 메모리"
  bulk(헤더 + [0x08,0,0,0] + 길이4바이트)
  bulk(Q565 데이터)
  write([0x36, 0x02])
  ```

- ★**대답을 반드시 확인해야 한다.** liquidctl 의 `_write_then_read` 는 한 번만
  읽고 그게 무슨 대답인지 안 본다. 크라켄은 안 물어본 상태 보고를 수시로
  올리므로, 그걸 "다 그렸다"로 착각하고 다음 장을 밀어넣게 된다. 앞 장이
  그려지는 중에 새 데이터가 들어가면 **화면이 찢어져 보인다.**
  머리 두 바이트(`0x37 0x02`)가 맞을 때까지 읽으면 사라진다.

- 한 장에 드는 시간 (11KB 와 48KB 가 거의 같다):
  ```
  시작 명령      2.0 ms
  데이터         1.1 ~ 3.4 ms   <- 데이터 크기는 병목이 아니다
  끝 명령의 대답  18.6 ~ 20.4 ms  <- 여기서 다 먹는다
  ```
  즉 장치가 스스로 초당 40장쯤에서 제동을 건다.

- 화면 방향 값이 3 이다. 보내기 전에 `rotate(orientation * -90)` 로 미리
  돌려놔야 똑바로 보인다.

- 화면이 **둥글다**. 640×640 사각형인데 보이는 건 그 안의 원이다. 원 바깥을
  검게 채우면 압축이 잘 돼 데이터가 20% 줄어든다.

### 모니터 전원 버튼은 윈도우에 아무 흔적도 안 남긴다

"화면이 꺼지면 조명도 끈다" 를 만들려면 화면이 꺼진 걸 알아야 하는데,
길이 하나가 아니었다. 실제로 재 본 결과다 (Dell AW3821DW, DisplayPort).

| 알아보는 길 | 절전으로 꺼질 때 | **전원 버튼으로 끌 때** |
|---|---|---|
| `GUID_CONSOLE_DISPLAY_STATE` 알림 | 온다 | **안 온다** |
| 붙어 있는 모니터 수(`SM_CMONITORS`) | 그대로 | **그대로** |
| 모니터에게 직접 묻기 (DDC/CI `0xD6`) | — | **이 모델은 지원 안 함** |
| **모니터 안 USB 허브가 빠지는가** | 그대로 | **빠진다** |

- 전원 버튼으로 끄면 화면이 잠든 것도 아니고 케이블이 빠진 것도 아니라
  윈도우가 아무것도 모른다. DDC/CI 로 물어보는 길이 있지만 전원 상태
  항목(VCP `0xD6`)은 지원하는 모델이 드물다. 이 모니터는 밝기(`0x10`)는
  대답하는데 `0xD6` 은 능력 목록에 아예 없었다.
- 남은 실마리는 **USB 허브**였다. 모니터가 꺼지면 품고 있던 허브가 통째로
  빠진다. 연결 해제 소리가 그래서 난다. 그걸 지켜보면 잡힌다.
- **`CM_Get_Device_ID_List` 에 `CM_GETIDLIST_FILTER_PRESENT` 를 꼭 줘라.**
  안 주면 "여태 본 적 있는 것" 을 다 돌려줘서, 장치가 빠져도 목록이 그대로다.
  변화가 없으니 아무 일도 안 일어난다 — 조용히 안 되는 쪽이라 찾기 어렵다.
- **`WM_DEVICECHANGE` 는 메시지 전용 창(`HWND_MESSAGE`)에 안 온다.** 진짜
  창을 만들되 보여주지 않으면(`WS_EX_TOOLWINDOW`, `ShowWindow` 안 부름) 받는다.
- 판단 규칙 둘. **배운 장치 중 하나라도 붙어 있으면 켜진 것으로 본다** —
  허브에 꽂아 둔 헤드셋만 빼도 꺼졌다고 하면 안 되니까. 그리고 **한 번도 본
  적 없는 장치는 판단에 안 쓴다** — 모니터 USB 선을 안 꽂은 사람의 조명이
  영영 안 켜지기 때문이다.
- 유휴 시간(`GetLastInputInfo`)으로 짐작하면 안 된다. 영상을 보는 중이면
  안 만져도 화면은 켜져 있고, 손으로 화면만 끄면 유휴 시간은 0 이다.

### 윈도우 특유의 함정

- **`time.sleep` 의 기본 해상도가 약 15.6ms 다.** 1ms 를 자라고 해도 15ms 를
  잔다. 초당 30장을 보내는 프로그램에서 이건 치명적이다 — 눈에는 "가끔 멈칫"
  으로 보인다. `winmm.timeBeginPeriod(1)` 로 올린다.
- **`.bat` 은 CP949 + CRLF, BOM 없이.** `chcp 65001` 과 한글이 같이 있으면
  cmd 가 파일 안에서 읽던 위치를 잃어 `echo` 한 줄이 조각나 실행된다.
- **`.ps1` 은 반대로 UTF-8 + BOM.** BOM 이 없으면 Windows PowerShell 5.1 이
  CP949 로 읽어서 한글이 깨지고 파싱이 실패한다. 창이 열렸다 즉시 닫히고
  로그도 안 남는다.
- **`.bat` 에서 `net session` 으로 관리자 판정을 하지 마라.** Server 서비스가
  꺼져 있으면 관리자여도 실패한다. 그러면 관리자로 올라간 자기 자신이 또
  자기를 띄워 **무한 증식**한다. UAC 가 조용히 통과되는 계정이면 프롬프트도
  없이 컴퓨터가 멈춘다. 실제로 그렇게 멈췄다. `fltmc` 를 쓰고, 재실행에는
  표식을 붙여 딱 한 번만 시도한다.
- 크롬 쿠키는 자동으로 못 가져온다. 켜져 있으면 파일을 독점으로 잠그고
  (`ERROR_SHARING_VIOLATION`), 크롬 127 이후는 앱 전용 암호화라 파일을 얻어도
  못 푼다. 확장으로 한 번 내보내 대시보드에 붙여넣는 수밖에 없다.

### 성능 숫자를 만들 때

- 한때 `lcd_fps` 가 **루프가 돈 횟수**를 세고 있었다. 보낼 게 없어 헛도는 것까지
  세는 바람에 "초당 200장" 이 나왔다. 장치 천장이 40장인데도.
- 대답을 안 기다리고 밀어넣었더니 "초당 60장" 이 나왔다. 빨라 보였지만
  화면은 찢어져 있었다.
- **숫자가 좋아졌는데 눈으로 확인 안 했으면 의심하라.**

## 안전장치

수랭을 다루는 프로그램이라 몇 가지를 못 하게 막아 뒀다.

- **펌프 하한 60%.** liquidctl 이 알려주는 하한은 20% 지만 그건 장치가 받는
  값일 뿐이다. 조용하자고 냉각을 포기할 수는 없다.
- **말이 안 되는 수온은 버린다.** 화면을 초당 몇십 장 보내는 중에 상태를 읽으면
  옛 응답을 집어 와 수온이 `0.0` 으로 읽힌다. 그걸 믿으면 "차가우니 펌프를
  줄여도 되겠다"고 판단한다. 실제로는 뜨거운데. 5~80°C 밖이면 그 회차를 버리고
  옛 값을 유지한다.
- **전송이 3번 연속 실패하면 화면을 스스로 끈다.** 냉각은 화면 없이도 돌아간다.
- **`owner.py`** 가 크라켄을 여는 모든 스크립트 앞에서 "지금 누가 쓰고 있나"를
  확인한다. 겹쳐 열면 장치가 굳어 전원을 끊어야 한다.

## 파일

| | |
|---|---|
| `tray.py` | **주인.** 준비를 시키고 대시보드를 자식으로 띄운다. 트레이 아이콘 |
| `dashboard.py` | 웹 대시보드. 조명 스레드 · 크라켄 스레드 · 화면 만드는 스레드 |
| `fan.py` | 리안리 허브 연결, 채널·자리 계산 |
| `effects.py` | 조명 효과 |
| `audio.py` | 스피커 루프백에서 소리 세기·주파수 |
| `kraken.py` | 수온·펌프·화면. 크라켄 연결을 하나만 들고 있다 |
| `lcd_stream.py` | LCD 전송 (Q565 빠른 경로, GIF 버킷 경로) |
| `lcd_monitor.py` | 화면 비추기·상태판·글자 그리기 |
| `video.py` | 유튜브·GIF 를 640 그림으로 |
| `parts.py` | 부품별 색, 자리 찾기 |
| `playlists.py` | 이름 붙인 재생목록과 대기열 |
| `display.py` | 모니터가 켜져 있나 (신호 셋). `--learn` 으로 전원 버튼을 배운다 |
| `settings.py` | 마지막 설정을 적어 두고 되돌린다. 이상한 값은 걸러낸다 |
| `specs.py` | 이 컴퓨터에 뭐가 꽂혀 있는지 |
| `owner.py` | 크라켄을 지금 누가 쥐고 있나 |
| `templates/index.html` | 대시보드 화면 |

`tools` 성격의 것들 (`probe_razer.py`, `map_rings.py`, `lcd_bench.py`,
`gpu_scan.py` …) 은 배치를 알아내거나 속도를 잴 때 쓴다.
